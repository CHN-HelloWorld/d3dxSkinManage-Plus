# 制作和安装语言包

语言由**文件夹名称**决定。每种语言只需要编辑一个 UTF-8 JSON 文件，不需要修改 Python、安装翻译软件或编译语言包。

```text
config/languages/
├── zh-CN/strings.json
├── en-US/strings.json
└── ja-JP/strings.json
```

## 安装、选择和修改

1. 打开「设置 → 个性化 → 外观」，点击「打开语言包文件夹」。这里就是程序正在读取的 `config/languages`，发行包已提供默认中英文文件。
2. 复制一个语言文件夹，改名为需要的语言代码，例如 `ja-JP`、`fr-FR`、`pt-BR`、`zh-Hant`。
3. 修改其中的 `strings.json`：保留左侧原文，填写右侧译文；在 `_meta.name` 中填写该语言的自称，例如 `日本語`。
4. 返回设置，点击「刷新列表」，选择新语言，然后重启软件。

修改当前语言包后也需要重启。语言切换不会重建正在执行导入、部署或下载的页面。

文件夹名称使用字母、数字、`-` 或 `_`，以字母开头，最长 64 个字符。推荐标准语言代码和连字符；`en_US` 这类下划线写法也能识别。不要同时创建仅大小写或连字符/下划线不同的同一语言目录。

## 文件格式

```json
{
  "$schema": "../schema.json",
  "_meta": {
    "format": 1,
    "name": "日本語",
    "author": "你的名字",
    "fallback": "en-US"
  },
  "messages": {
    "设置": "設定",
    "搜索当前页面": "このページを検索",
    "正在导入 {count} 个 Mod": "{count} 個の Mod をインポート中"
  },
  "gamebanana": {
    "Skins": "スキン",
    "Characters": "キャラクター",
    "Weapons": "武器"
  },
  "qt": {
    "Cancel": "キャンセル",
    "&Yes": "はい(&Y)",
    "&No": "いいえ(&N)"
  }
}
```

- `messages`：应用原文 → 译文，包含页面、提示、弹窗、任务进度、设置和快捷键说明。
- `gamebanana`：GameBanana 返回的原始名称 → 译名。分类面包屑、分类选择列表和类型徽章使用这里，新增网站分类也可直接添加。匹配兼容大小写差异。接口返回值、缓存和自动安装匹配仍保留原始名称。
- `qt`：Qt 标准按钮等控件的源文案 → 译文。随包提供常用按钮；也会加载 Qt 官方对应语言的翻译。插件使用 Qt 标准翻译入口时可读取 `messages`。
- `_meta.name`：设置列表里的显示名称；不决定语言身份。`author` 可选。
- `_meta.fallback`：可选的后备语言。可以只翻译一部分，其余使用这个语言；未设置时，应用文字回退原文，GameBanana 名称回退接口原名。
- `$schema`：可选，指向本目录的 `schema.json`。VS Code 等支持 JSON Schema 的编辑器会据此提示字段，并检查结构和字段类型，例如提示 `messages` 中的译文必须是字符串。它不保存译文，也不决定语言；软件加载语言包时不读取它，运行时校验由程序完成。语言包作者无需编辑此文件。

简单的 `{ "原文": "译文" }` 顶层字典也支持，等同于只提供 `messages`。需要翻译 GameBanana 或标准按钮时使用上面的分区结构。

空译文表示「尚未翻译」，会自动回退。不要重复同一个 JSON 键，也不要在最后一项后保留逗号。支持带 BOM 的 UTF-8 文件。

## 动态内容、换行和富文本

`{count}`、`{name}`、`{value}` 等由软件填入数据。可以调整整段占位符的位置，但**不要改动占位符内部**，包括格式和转换标记，例如 `{count:,}`、`{size:.1f}`、`{value!r}`。软件会检查这些标记，错误的单条译文会回退。

```json
{
  "已导入 {count} 个 Mod": "Imported Mods: {count}",
  "当前项：{name}": "Current item: {name}",
  "读取失败: {e}": "Read failed: {e}"
}
```

保留 `\n` 换行、HTML 标签、链接中的占位符和文件筛选器里的 `*.zip` 等扩展名模式。Qt 的 `%1`、`%n` 也是占位符，`&` 可以表示按钮助记键。推荐使用「Mods: {count}」这类不依赖单复数变化的数量表达。

游戏/Mod/预设名称、作者描述、自定义标签等用户内容保持原样。诊断日志、协议标识、INI 键名和文件路径不做词语替换。操作系统原生窗口中的系统文本由系统提供。

## 存放位置和自动更新

- 源码运行和发行版都从配置目录中的 `languages/` 读取语言，即应用数据根的 `config/languages/`。设置中的打开按钮会打开实际使用的目录。
- 每种语言只有一份 `strings.json`，直接编辑该文件即可。没有内置包与用户包的叠加层，也没有另一份原文映射资源。
- standalone 和 onefile 发行包都会把默认中英文文件放在 EXE 旁的 `config/languages/`。拷贝 onefile 版本时也要带上这个目录。
- 自动更新保留已有语言文件，仅补充尚不存在的语言文件，不覆盖用户修改。新增文案若还没有译文，会回退原文，可由语言包作者补齐。

可以制作只含部分译文的语言包，其余文案使用 `_meta.fallback` 指定的语言或原文。修改默认语言中的几句话时，在现有文件中直接修改对应条目即可。

## 开发者工具

在源码根目录运行：

```powershell
# 从显式翻译调用、静态标记和内置插件清单更新中文模板
python scripts/i18n/i18n_catalog.py --update

# 生成一份空译文模板；不会覆盖已经存在的语言包
python scripts/i18n/i18n_catalog.py --new ja-JP --name 日本語

# 检查 JSON、重复键、类型和占位符；允许第三方语言包不完整
python scripts/i18n/i18n_catalog.py --check

# 发布前要求指定语言覆盖所有应用原文
python scripts/i18n/i18n_catalog.py --check --require-complete en-US
```

工具直接扫描当前源码，更新中文模板、创建新语言包并检查翻译覆盖率，不生成源码位置清单。

原文是唯一的翻译键：代码调用 `t("设置")`，语言包就在 `messages` 中提供 `"设置": "Settings"`。语言包作者只需编辑本目录下各语言的 `strings.json`。

新增普通文字用 `t("原文")`；带参数时用 `t("已导入 {count} 个 Mod", count=count)`，不要先拼接动态值再翻译。模块常量和默认参数用 `N_("原文")` 标记，在显示时调用 `t()`。API 数据、枚举值和持久化设置与显示文字分开保存，列表应使用 `itemData` 存储真实值。

通过变量、回调传给界面的原文也要在定义处加 `N_()`。不应加载应用配置的底层模块可以从 `src.utils.language_pack` 导入这个纯标记函数，提取工具同样识别。

语言包只作为数据读取；翻译过程不扫描窗口、不修改源文档或自动重写用户的语言包。
