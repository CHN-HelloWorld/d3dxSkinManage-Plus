# 预设检查

本插件是**教学示例**，用于演示插件开发，也可实际使用。

集中列出当前游戏组合预设中失效的 Mod 和命名外观变体引用，便于在切换前整理预设。需要宿主 1.0.0、SDK 2.0。

清单显式声明 `onStartup`，使启用后立即注册导航页；命令型插件通常可以省略启动激活。

## 使用

启用插件后进入新增的「预设检查」导航页。检查表显示预设名、Mod 名和失效原因，悬停可查看稳定 ID。
「包含默认预设」选项会保存到插件自己的存储中，重载后仍保留。

导入、删除、更新 Mod、应用预设、重建索引、切换游戏或变体状态改变后，可见页面会重新检查。
隐藏页面不读取变体文件；进入页面后逐个查询并显示进度，离开页面即停止本轮检查。
创建、删除或重命名预设没有独立的 SDK 事件；重新进入页面或点击「重新检查」即可更新。
检查只读取当前快照，不修改预设；请回到主界面重新选择 Mod 或外观变体。

选择默认配置（变体 ID 为 `None`）属于有效状态。检查结果表示引用是否存在，不验证 Mod 文件完整性、
变体内容与当前源码的兼容性，也不能判断不同 Mod 在游戏中的视觉冲突。读取失败时会显示「检查未完成」。

## 教学重点

- `audit_presets()`：按 `preset_id`、`mod_id`、`variant_id` 检查引用，不用显示名称替代身份。
- `unresolved_mod_ids`：读取预设保存但当前索引无法解析的引用，预设重载后仍能显示缺失项。
- `PresetAuditPage`：使用标准 PySide6 控件；让宿主负责主题和页面所有权。
- `schedule_refresh()`：合并同一轮事件循环的通知，忽略其他游戏的变化。
- `_begin_scan()` / `_advance()`：重新取得不可变快照，每轮事件循环读取一个 Mod 的变体列表。
  同一 Mod 只查询一次；切换游戏或离开页面后丢弃未完成批次。
- `stop()` / `deactivate()`：先停止页面定时器，再由宿主释放控件和事件订阅。

`mods:read` 用于查询；`storage` 保存筛选偏好；`ui:views` 声明导航页。
页面由 `register_page()` 注册，无需重复声明 `contributes.views`，后者用于插件详情中的内嵌视图。
