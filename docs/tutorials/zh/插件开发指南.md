# 插件开发指南

这份指南面向会使用 Python、希望为 d3dxSkinManage-Plus 编写扩展工具的开发者。软件按游戏管理 Mod、分类、组合预设和外观变体；插件适合把这些公开能力组合成专门的整理、检查和操作工具。

插件通过 `src.plugin_sdk` 访问宿主，可以拆分为 Python 包、声明插件依赖、按需激活并提交后台任务。第三方 Python 依赖不会自动安装；用户通过压缩包或插件目录安装扩展。

建议先用第 1 节的骨架确认命令可以运行，再按以下顺序阅读三个随包示例。每个示例都有可直接启用的清单、源码、英文语言包和使用说明；无需同时启用。

| 顺序 | 实用示例 | 用途 | 主要教学内容 |
| --- | --- | --- | --- |
| 1 | [Mod 清单导出](../../../plugins/example.mod-inventory/README.md) | 导出当前游戏或分类子树的 CSV 清单 | 多文件组织、按需命令、配置、后台计算与原子文件保存 |
| 2 | [预设检查](../../../plugins/example.preset-audit/README.md) | 找出组合中失效的 Mod 和变体引用 | 未解析引用、启动激活、页面、事件、分批查询与清理 |
| 3 | [预设轮换](../../../plugins/example.preset-cycle/README.md) | 通过快捷键或按钮切换前后组合 | 写权限、异步任务、重复请求、完成反馈与取消 |

第 10 节给出逐个示例的阅读和练习步骤。接口查询见第 2–9 节，自定义界面见第 11 节，开发验证和排障见第 12 节。

## 1. 环境与第一个插件

### 1.1 准备环境

使用 Windows 10/11 x64 和 Python 3.10–3.14，推荐在源码环境中开发。在仓库根目录运行；已有开发环境时跳过前两条：

```powershell
python -m venv .venv
& ".venv/Scripts/python.exe" -m pip install -e ".[dev]"
& ".venv/Scripts/python.exe" run_app.py
```

先确认主程序可以启动，再添加一个测试游戏和少量占位 Mod。第一个插件只读取数据；预设轮换会改变部署，应在测试库检查成功、失败和取消结果。

### 1.2 生成并启用骨架

```powershell
& ".venv/Scripts/python.exe" scripts/plugins/new_plugin.py com.example.mod-summary --name "Mod 统计助手" --author "示例作者"
```

生成的目录为：

```text
plugins/com.example.mod-summary/
├── plugin.json
├── entry.py
├── commands.py
├── languages/en-US/strings.json
└── README.md
```

在应用「插件」页点击「打开插件目录」，确认可以看到这个文件夹，然后「重新扫描」并开启插件，阅读首次信任与权限提示。在工具箱或导航区「插件命令」中执行「查看 Mod 统计」，会显示当前游戏的 Mod 总数和已启用数；未选游戏时会提示先选择游戏。

默认快捷键是 `Ctrl+Alt+M`，可在「设置 → 快捷键」中调整。冲突时不会覆盖已有绑定。命令返回的 Python 字典供调用者使用，可见提示由插件自己调用 `notify()` 显示。

目标目录已存在时，脚手架停止且不覆盖文件。`--dir` 指定插件目录的父目录，例如 `--dir "$env:TEMP/plugin-demo"` 输出 `$env:TEMP/plugin-demo/com.example.mod-summary/`；宿主只扫描实际插件目录，不会自动扫描其他开发目录。

### 1.3 理解最小实现

脚手架将生命周期与命令逻辑分别放在 `entry.py` 和 `commands.py`。下面是便于手动创建的单入口最小插件。文件用 UTF-8 保存，清单必须是标准 JSON。

`plugin.json`：

```json
{
  "id": "com.example.mod-summary",
  "name": "Mod 统计助手",
  "version": "0.1.0",
  "apiVersion": "2.0",
  "minAppVersion": "0.1.0",
  "author": "示例作者",
  "description": "Mod 统计助手 插件",
  "entry": "entry.py",
  "files": ["entry.py"],
  "permissions": ["mods:read", "ui:tools-page", "ui:shortcuts"],
  "contributes": {
    "commands": [
      {"id": "com.example.mod-summary.summary", "title": "查看 Mod 统计"}
    ],
    "toolsPage": [
      {"command": "com.example.mod-summary.summary", "group": "插件"}
    ],
    "shortcuts": [
      {"command": "com.example.mod-summary.summary", "default": "Ctrl+Alt+M", "context": "window"}
    ]
  }
}
```

`entry.py`：

```python
"""插件入口：只依赖公开 SDK。"""

from __future__ import annotations

from src.plugin_sdk import PluginBase, PluginContext


class Plugin(PluginBase):
    """通过公开 SDK 查询当前游戏并显示 Mod 启用数量。"""

    def activate(self, ctx: PluginContext) -> None:
        """保存插件上下文并注册统计命令。"""
        self._ctx = ctx
        ctx.commands.register("com.example.mod-summary.summary", self._summary)
        ctx.logger.info("插件已激活：%s", ctx.meta.name)

    def _summary(self, **_) -> dict[str, int]:
        """显示当前游戏的 Mod 总数与启用数，并返回可供其他命令使用的结果。"""
        tr = self._ctx.i18n.t
        if not self._ctx.game.current_game_id():
            self._ctx.ui.notify(tr("请先选择一个游戏。"), "warning")
            return {"mods": 0, "enabled": 0}
        mods = self._ctx.mods.get_mods()
        enabled = sum(mod.enabled for mod in mods)
        self._ctx.ui.notify(tr("共 {total} 个 Mod，已启用 {enabled} 个。", total=len(mods), enabled=enabled))
        return {"mods": len(mods), "enabled": enabled}

    def deactivate(self) -> None:
        """记录插件停用日志。"""
        self._ctx.logger.info("插件已停用：%s", self._ctx.meta.name)
```

清单声明用户看到的入口，`activate()` 将命令 ID 绑定到处理函数。清单与注册 ID 必须相同。每次执行时重新查询当前游戏，不把旧快照当成实时模型。

声明的命令会自动成为激活入口，因此不必再写 `onCommand`。启用后显示「待命」是正常状态：宿主已经登记按钮和快捷键，首次使用时才执行入口。语言包格式见第 7.5 节。
